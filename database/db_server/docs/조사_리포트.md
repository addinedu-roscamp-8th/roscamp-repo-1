## 2. 프로젝트 개요

- **이름**: Sandwich Server (db_server)
- **역할**: 음식 판매점의 **주문**, **원재료**, **메뉴 레시피**를 관리하는 **Flask REST API 서버**
- **기술 스택**: Flask 3.0, PostgreSQL 16.11 + TimescaleDB, SQLAlchemy 2.0, Alembic, Flasgger(Swagger UI), Python 3.8+

---

## 3. 주요 기능

### 3.1 주문 관리 (store_order)
- 주문 생성(POST /orders), 목록/상세 조회, 상태 변경(PATCH)
- 주문 관리 웹 UI (`/orders-ui`): 목록, 검색, 필터, 새 주문, 상세, 상태 변경
- 트랜잭션: `SELECT ... FOR UPDATE` 로 행 잠금, 멱등성 고려

### 3.2 원재료 관리 (store_ingredient_mst / store_ingredient_txn)
- 원재료 마스터 CRUD, 카테고리/활성 상태
- 원재료 거래 이벤트 생성/조회 (입고·사용·폐기·조정)
- TimescaleDB hypertable 기반 시계열 저장

### 3.3 메뉴 레시피 BOM (store_menu_recipe_bom)
- 메뉴별 레시피 조회/생성/업데이트/삭제
- 메뉴 SKU ↔ 원재료 SKU, 수량(qty_per_menu)

### 3.4 재고 (store_inventory_txn, 예비)
- 예비 테이블로 최소 REST API만 제공 (POST/GET /inventory/txn)
- 대시보드·분석에서는 사용하지 않음

### 3.5 분석 API (TimescaleDB Continuous Aggregates)
- 일별 재고 변동량 (`cagg_daily_inventory_change`)
- 일별 판매량 (`cagg_daily_sales_qty`)
- TOP 판매 상품
- CAGG 뷰 없을 때 Fallback 로직으로도 동작

### 3.6 대시보드·헬스
- 웹 대시보드 (`/dashboard`): 실시간 통계, 최근 주문, 재고 요약, 인기 상품 TOP 5, 30초 자동 새로고침
- 헬스: `/health`, `/db/status` (TimescaleDB 상태)
- Swagger UI: `/api-docs`, OpenAPI 스펙 `/apispec.json`

## 4. 데이터베이스 구조 요약

| 테이블 | 용도 |
|--------|------|
| store_order | 주문 ID, 채널, 상태, 고객정보, 항목(JSONB), 금액, 결제상태 |
| store_ingredient_mst | 원재료 마스터 (SKU, 이름, 카테고리, 단위, 활성) |
| store_ingredient_txn | 원재료 거래 (hypertable) |
| store_menu_recipe_bom | 메뉴별 원재료 BOM |
| store_inventory_txn | 재고 거래 (예비, 최소 기능) |

## 6. 결론

db_server는 **샌드위치 스타일 매장의 주문·원재료·메뉴 레시피**를 PostgreSQL/TimescaleDB로 다루는 **Flask REST API + 웹 대시보드/주문 UI** 서버이며, 현재 스테이징된 파일은 앱 코드, 마이그레이션, 스크립트, 문서, 테스트를 포함한 **전체 서비스 구성**을 반영하고 있습니다.
