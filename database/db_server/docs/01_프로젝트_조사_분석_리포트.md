## 3. 현재 앱이 대상으로 하는 DB 구조 (models.py)

현재 **app/models.py** 는 아래 테이블에 대응됩니다 (스키마명이 **schema.sql 과 다름**).

| 모델 | 테이블명 | 용도 |
|------|----------|------|
| StoreOrder | store_order | 주문 (channel, status, items JSONB, total_amount 등) |
| StoreInventoryTxn | store_inventory_txn | 재고 거래 (sku, qty_delta, txn_type, order_id) |
| StoreIngredientMst | store_ingredient_mst | 원재료 마스터 (ingredient_sku, category, base_unit) |
| StoreIngredientTxn | store_ingredient_txn | 원재료 거래 (hypertable 가정, txn_type 등) |
| StoreMenuRecipeBom | store_menu_recipe_bom | 메뉴별 BOM (menu_sku, ingredient_sku, qty_per_menu) |

- **config**: `Config.SQLALCHEMY_DATABASE_URI` → `postgresql://USER:PASSWORD@HOST:PORT/DB_NAME` (환경변수: DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD)
- **DB 접근**: `get_db()` 로 세션 획득, `db.close()` / `db.rollback()` 로 정리
- **API 문서**: Flasgger 사용. `/api-docs` (Swagger UI), `/apispec.json` (OpenAPI 2.0). 각 라우트에 docstring YAML로 스펙 기술

## 4. schema.sql (Kitchmatic) 에 정의된 테이블

실제 DB에 **schema.sql 기준으로 테이블을 생성했다**고 가정한 구조입니다.

| 테이블 | PK | 주요 컬럼 | 비고 |
|--------|-----|-----------|------|
| menus | id (VARCHAR) | name, price, category, available | 초기 데이터 M001~M003 |
| ingredients | id (VARCHAR) | name, unit, category, items_per_box | 초기 데이터 I001~I006 |
| recipes | id (UUID) | menu_id(FK), name, estimated_time_seconds | |
| recipe_steps | id (UUID) | recipe_id(FK), step_order, action, ingredient_id, quantity, unit, robot_arm, duration_seconds | ARM_1/ARM_2 |
| inventory | id (UUID) | ingredient_id(FK), location, current_stock, min_threshold, max_capacity | STOCK_AREA/INGREDIENT_BED |
| inventory_transactions | id (UUID) | inventory_id(FK), transaction_type, quantity, before_stock, after_stock, order_id, robot_id | REPLENISHMENT/CONSUMPTION/REPLACEMENT |
| robots | id (UUID) | name, type, status, ip_address, port | ARM_1/ARM_2, SERVING_BOT_1~3 |
| orders | id (UUID) | table_number, menu_id(FK), quantity, status, assigned_robot_arm_id, assigned_serving_bot_id | PENDING~COMPLETED 등 |
| quality_check_results | id (UUID) | order_id(FK), status, confidence_score, attempt_number, robot_arm_id | NORMAL/ABNORMAL |

- **현재 앱 모델(store_*)과 schema.sql(menus, orders, recipes 등)은 서로 다른 스키마**입니다.
- 요청사항: **schema.sql 기준 테이블에 대한 CRUD REST API**를 구현하고, API 문서(api docs)에 상세 명세를 제공하는 것입니다.

## 7. 결론 및 권장 방향

- **현재 상태**: db_server는 **store_*** 테이블용 모델·라우트·서비스로 구성되어 있고, **schema.sql(Kitchmatic)** 테이블(menus, ingredients, recipes, recipe_steps, inventory, inventory_transactions, robots, orders, quality_check_results)용 코드는 없음.
- **요청사항 반영 방향**  
  1. **schema.sql 기준**으로 SQLAlchemy 모델 추가(또는 별도 모델 파일로 분리).  
  2. 각 리소스별 **REST CRUD API** 추가 (생성·목록·상세·수정·삭제 등).  
  3. Flasgger docstring으로 **모든 API 상세 명세**를 작성해 `/api-docs` 에서 제공.  
  4. **전체 API에 대한 테스트**를 작성·실행하고, 실패 시 원인 분석 및 수정 계획 수립.

이 리포트는 위 방향으로 02(CRUD·API 문서), 03(테스트·리포트) 작업의 입력으로 사용합니다.
