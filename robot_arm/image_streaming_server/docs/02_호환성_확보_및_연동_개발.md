# 호환성 확보 및 연동 개발 문서

이 문서는 **이미지 처리 서버(Flask 웹캠 서버)** 와 **AI 서버(영상/이미지 분석)** 간 연동 시, API 엔드포인트별 호환성 고려사항과 기존 연동 내용을 업데이트하는 방법을 정리합니다.

---

## 1. 문서 목적 및 대상

- **목적**: 이미지 처리 서버 개선 반영 후, AI 서버에서 동일하게 영상/이미지 분석을 활용할 수 있도록 **호환성 유지** 및 **선택적 연동 확장** 가이드 제공.
- **대상**: AI 서버 개발자, 연동 담당자.  
- **참고**: 변경사항 요약은 `01_변경사항_요약.md` 참고.

---

## 2. API 엔드포인트 목록 (이미지 처리 서버)

| 메서드 | 경로 | 용도 | AI 서버 연동 |
|--------|------|------|--------------|
| GET | `/` | 서비스·엔드포인트 안내 | 선택(디스커버리) |
| GET | `/health` | 서버/카메라 상태 | 권장(헬스체크) |
| GET | `/video_feed` | MJPEG 영상 스트림 | **기존 연동 유지** |
| GET | `/snapshot` | 단일 이미지 다운로드(분석용) | **기존 연동 유지** |
| GET | `/snapshot/inline` | 단일 이미지 인라인 반환 | 선택 |
| GET | `/test` | WebSocket 테스트 페이지 | 불필요 |
| WS | `/ws/video` | WebSocket 영상 푸시 | **추가 연동 시** |

## 3. 엔드포인트별 호환성 및 연동 업데이트

### 3.1 GET `/health`

- **역할**: 서버·카메라 동작 여부 확인.
- **응답 형식**: `{"ok": true, "camera_ready": bool, "device": "/dev/..."}`.
- **호환성**: **변경 없음**. 기존처럼 사용 가능.
- **연동 업데이트**:
  - **필수 변경 없음.**  
  - 카메라 재연결 로직 추가로, 일시적으로 `camera_ready: false` 후 다시 `true`로 바뀔 수 있음. 재시도/대기 로직이 있다면 그대로 유지.

---

### 3.2 GET `/snapshot`

- **역할**: 호출 시점의 한 장을 JPEG로 다운로드 (AI 분석용).
- **요청**: `GET {base_url}/snapshot` (예: `http://192.168.1.10:5000/snapshot`).
- **응답**: `Content-Type: image/jpeg`, `Content-Disposition: attachment; filename="snapshot.jpg"`, 본문은 JPEG 바이너리.
- **호환성**: **동일**. URL·헤더·본문 형식 변경 없음.
- **변경된 점**: JPEG 품질만 85로 고정 (설정 가능). 해상도는 **원본 유지**.
- **연동 업데이트**:
  - **AI 서버 `source_fetcher.get_snapshot_image()`**: **수정 불필요.**  
  - **설정**: `config/jetbot_config.yaml` 의 `base_url`, `endpoints.snapshot` 그대로 사용.

```yaml
# jetbot_config.yaml (변경 없음)
base_url: "http://192.168.1.10:5000"
endpoints:
  snapshot: "/snapshot"
  video_feed: "/video_feed"
```

---

### 3.3 GET `/video_feed` (MJPEG 스트림)

- **역할**: MJPEG 스트림으로 영상 전송. `multipart/x-mixed-replace; boundary=frame` 형식, 각 파트는 JPEG.
- **요청**: `GET {base_url}/video_feed`, `stream=True` 로 연속 수신.
- **호환성**: **프로토콜·형식 동일**. 기존 MJPEG 파싱 로직 그대로 사용 가능.
- **변경된 점**:
  - **해상도**: 가로가 640px 초과인 경우 **최대 640px로 리사이즈**된 프레임이 전송됨. (이미지 처리 서버 `STREAM_MAX_WIDTH` 로 변경 가능, 0이면 리사이즈 없음)
  - **품질**: JPEG 품질 82 적용 (`STREAM_JPEG_QUALITY`).
- **연동 업데이트**:
  - **AI 서버 `get_video_frames()`, `stream_video_frames()`**: **로직 수정 불필요.**  
    - `requests.get(url, stream=True)` + `iter_content()` + `\xff\xd8` / `\xff\xd9` 파싱 그대로 유효.
  - **고려사항**:
    - 분석 모델 입력 크기가 **640px 기준**이면 그대로 사용.
    - **더 큰 해상도**가 필요하면:
      - 이미지 처리 서버에서 `STREAM_MAX_WIDTH` 를 늘리거나 `0`으로 설정하거나,
      - 분석용으로는 **`/snapshot`** 을 사용하는 구간은 그대로 두면 됨 (스냅샷은 원본 해상도).
  - **설정**: `jetbot_config.yaml` 의 `endpoints.video_feed`, `video.timeout_seconds`, `video.num_frames`, `video.frame_interval_ms`, `video.stream_timeout_seconds` 등 **기존대로** 사용.

---

### 3.4 GET `/snapshot/inline`

- **역할**: 스냅샷 한 장을 `Content-Disposition` 없이 `image/jpeg` 로 반환 (브라우저 인라인 표시 등).
- **호환성**: **동일**. 품질만 85 적용.
- **연동 업데이트**: AI 서버에서 사용 중이었다면 **변경 없음**. 사용하지 않았다면 무시.

---

### 3.5 GET `/` (인덱스)

- **역할**: 서비스명·엔드포인트 목록 반환.
- **응답 예**: `{"service": "webcam", "endpoints": {"video": "/video_feed", "snapshot": "/snapshot", "health": "/health", "ws_video": "/ws/video", "test_page": "/test"}}`.
- **호환성**: 기존 키 유지. **추가 키** `ws_video`, `test_page` 만 있음.
- **연동 업데이트**:
  - 엔드포인트를 **하드코딩**이 아니라 **`/` 응답에서 읽는** 경우: 새 키는 **무시**하거나, 필요 시 `ws_video` 만 추가로 처리.
  - **설정 파일**(`jetbot_config.yaml`) 기반이라면 **변경 없음.**

---

### 3.6 WebSocket `/ws/video` (신규)

- **역할**: 브라우저/클라이언트에 **JPEG 바이너리 프레임**을 푸시. MJPEG와 동일한 공유 버퍼 소스.
- **프로토콜**: WebSocket. 서버 → 클라이언트 방향으로만 JPEG 바이트 전송.
- **호환성**: **신규 엔드포인트**. 기존 AI 서버 연동과는 **독립**.
- **연동 업데이트 (선택)**:
  - **현재**: AI 서버는 **HTTP MJPEG(`/video_feed`)만 사용**하면 됨. WebSocket 연동은 **필수 아님**.
  - **추가 연동 시** 고려사항:
    - **URL**: `ws://{host}:5000/ws/video` (SSL 사용 시 `wss://`).
    - **수신**: 바이너리 프레임(JPEG) 수신 → `np.frombuffer(..., dtype=np.uint8)` + `cv2.imdecode()` 로 BGR 배열 복원.
    - **설정**: `jetbot_config.yaml` 에 `ws_video: "/ws/video"` 등 추가하고, WebSocket 전용 fetcher/클라이언트 모듈을 두는 방식 권장.
  - 영상 스트리밍 작업 완료 후, **WebSocket 클라이언트를 추가할 때** 위 사항을 반영하면 됨.

## 4. AI 서버 측 연동 요약

| 구성 요소 | 조치 | 비고 |
|-----------|------|------|
| **config/jetbot_config.yaml** | 변경 없음 | `base_url`, `endpoints.snapshot`, `endpoints.video_feed` 유지 |
| **source_fetcher.get_snapshot_image()** | 변경 없음 | `/snapshot` 호출·디코딩 동일 |
| **source_fetcher.get_video_frames()** | 변경 없음 | `/video_feed` MJPEG 파싱 동일 |
| **source_fetcher.stream_video_frames()** | 변경 없음 | 동일 |
| **app.py** (분석 API) | 변경 없음 | snapshot/video_feed 소스 그대로 사용 |
| **WebSocket 연동** | 선택 사항 | 추후 `/ws/video` 클라이언트 추가 시 문서·설정 반영 |

---

## 5. 검증 체크리스트

연동 개발/배포 후 아래로 호환성을 확인할 수 있습니다.

- [ ] `GET {base_url}/health` → `ok`, `camera_ready` 확인
- [ ] `GET {base_url}/snapshot` → JPEG 다운로드, `get_snapshot_image()` 로 BGR 배열 정상 획득
- [ ] `GET {base_url}/video_feed` (stream=True) → MJPEG 파싱으로 프레임 수신, `get_video_frames()` / `stream_video_frames()` 동작
- [ ] 분석 API (예: `/analyze/snapshot`, `/analyze/video`, `/analyze/video/stream`) 가 기존과 동일한 소스·형식으로 동작
- [ ] (선택) WebSocket 연동 시 `ws://.../ws/video` 접속 후 바이너리 JPEG 수신·디코딩 확인
