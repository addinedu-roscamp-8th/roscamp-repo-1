# 이미지 처리 서버 변경사항 요약 (AI 서버 분석 연동용)

이 문서는 Flask 웹캠 서버(이미지 처리 서버)의 개선 개발 내용을 정리하며, **AI 서버에서 영상/이미지 분석에 활용할 때** 참고할 변경 사항을 중심으로 기술합니다.

---

## 1. 변경 개요

| 구분 | 변경 전 | 변경 후 |
|------|---------|---------|
| **스트리밍 구조** | `/video_feed` 접속자마다 스레드가 **각자 JPEG 인코딩** | **인코더 스레드 1개**가 공유 JPEG 버퍼 1개만 갱신, `/video_feed`는 버퍼만 읽어 전달 |
| **프레임 소스** | `/video_feed`: 매 요청마다 `_get_latest_frame()` → `cv2.imencode()` | `/video_feed`: `_get_latest_jpeg()`로 **이미 인코딩된 바이트**만 읽어 MJPEG 청크로 yield |
| **카메라 오류** | `read()` 실패 시 `_latest_frame` 갱신 중단 → 동일 프레임만 반복 | 연속 실패 시 **자동 재연결** (실패 횟수·재연결 대기 시간 설정 가능) |
| **클라이언트 끊김** | 끊어져도 스레드가 계속 인코딩·전송 시도 | `GeneratorExit` 처리로 루프 정상 종료, 리소스 해제 |
| **스트림 해상도/품질** | 원본 해상도, 인코딩 옵션 없음 | 스트림: 가로 최대 640px 리사이즈, JPEG 품질 82 / 스냅샷: 품질 85 (설정으로 변경 가능) |
| **WebSocket** | 없음 | **`/ws/video`** 추가 — 동일 공유 JPEG를 바이너리 프레임으로 푸시 |

---

## 2. API 동작 변경 (AI 서버 연동 관점)

### 2.1 `/video_feed` (MJPEG 스트림)

- **호환성**: **동일**. `multipart/x-mixed-replace; boundary=frame` 형식과 JPEG 바이트 구조는 그대로입니다.
- **변경점**:
  - 서버 내부만 변경: 이제 **공유 버퍼에서 읽은 JPEG**를 그대로 보냅니다.
  - **스트림 해상도**: 가로가 640px 초과일 경우 **640px로 리사이즈된 프레임**이 전송됩니다. (설정 `STREAM_MAX_WIDTH = 640`, 0이면 리사이즈 없음)
  - **JPEG 품질**: `STREAM_JPEG_QUALITY = 82` 적용. (분석에 무리 없는 수준)
- **AI 서버 영향**:
  - `source_fetcher.get_video_frames()`, `stream_video_frames()` 등 **기존 MJPEG 파싱 로직 그대로 사용 가능**.
  - 단, **해상도가 640px 이하로 올 수 있음** — 학습/추론 시 입력 크기를 640 기준으로 두었다면 그대로 사용 가능. 더 큰 해상도가 필요하면 이미지 처리 서버의 `STREAM_MAX_WIDTH`를 늘리거나 0으로 설정.

### 2.2 `/snapshot`

- **호환성**: **동일**. 단일 JPEG 다운로드, `Content-Disposition: attachment`, `download_name="snapshot.jpg"` 유지.
- **변경점**:
  - **원본 해상도 유지** (리사이즈 없음). **JPEG 품질만** `SNAPSHOT_JPEG_QUALITY = 85` 적용.
- **AI 서버 영향**:
  - `get_snapshot_image()` 호출 방식·응답 형식 변경 없음. 분석 품질을 위해 스냅샷은 원본 해상도 + 품질 85로 유지.

### 2.3 `/snapshot/inline`

- **호환성**: **동일**. JPEG 바이트를 `Content-Type: image/jpeg`로 그대로 반환.
- **변경점**: `/snapshot`과 동일하게 품질 85 적용, 리사이즈 없음.

### 2.4 `/health`

- **호환성**: **동일**. `ok`, `camera_ready`, `device` 필드 유지.
- **변경점**: 없음. 카메라 재연결 로직으로 `camera_ready`가 일시적으로 `false`였다가 복구되는 경우만 추가됨.

### 2.5 `GET /` (인덱스)

- **호환성**: 기존 필드 유지.
- **추가**: `endpoints`에 **`ws_video`**(`/ws/video`), **`test_page`**(`/test`) 가 포함될 수 있음. AI 서버가 인덱스만 파싱한다면 새 키는 무시하면 됨.

### 2.6 `/ws/video` (WebSocket, 신규)

- **역할**: 브라우저 등 클라이언트에 **JPEG 바이너리 프레임**을 푸시. 공유 JPEG 버퍼와 동일 소스.
- **AI 서버**: 현재 연동 대상 **아님**. 영상 스트리밍 작업 완료 후, 선택적으로 WebSocket 클라이언트를 추가할 때 참고.

## 3. 설정 상수 (이미지 처리 서버 측)

AI 서버 연동·분석 품질과 관련된 설정은 `flask_webcam_server.py` 상단에서 다음처럼 정의되어 있습니다.

| 상수 | 기본값 | 설명 |
|------|--------|------|
| `STREAM_MAX_WIDTH` | 640 | 스트림용 가로 최대 픽셀 (0이면 리사이즈 없음) |
| `STREAM_JPEG_QUALITY` | 82 | 스트림 JPEG 품질 (0–100) |
| `SNAPSHOT_JPEG_QUALITY` | 85 | 스냅샷 JPEG 품질 (0–100) |
| `DEFAULT_FPS` | 10 | 스트림/WebSocket 전송 목표 FPS |

분석 요구사항에 따라 위 값들을 조정하면 됩니다.

---

## 4. 요약: AI 서버에서 할 일

- **기존 HTTP 연동 (`/video_feed`, `/snapshot`, `/health`)**: **코드 변경 없이** 그대로 사용 가능.
- **주의할 점**: `/video_feed`로 받는 이미지가 **최대 가로 640px·품질 82**일 수 있음. 해상도/품질 요구가 크면 이미지 처리 서버 설정 조정 또는 `/snapshot` 위주 사용.
- **WebSocket (`/ws/video`)**: 별도 연동 개발 시 “호환성 확보 및 연동 개발” 문서의 WebSocket 섹션 참고.
