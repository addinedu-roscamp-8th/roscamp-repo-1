================================================================================
KEY FEATURES
================================================================================

1. NAMESPACE STRATEGY
   - Robot Side: NO namespace (simple topic names)
   - Main PC Side: WITH namespace (robot isolation)
   - Bridge: Uses 'remap' feature to add/remove namespace

2. DOMAIN ID ASSIGNMENT
   - Main PC (FMS): Domain 25
   - pinky1: Domain 11
   - pinky2: Domain 12
   - Robot Arm A: Domain 20
   - Robot Arm B: Domain 21

3. TOPIC FLOW EXAMPLES

   Example 1: Robot → Main PC (Sensor Data)
   ┌──────────┐           ┌──────────┐           ┌──────────────────┐
   │  pinky1  │──/odom──▶│  Bridge  │──/pinky1/─▶│     Main PC      │
   │ (D=11)   │           │          │    odom   │     (D=25)       │
   └──────────┘           └──────────┘           └──────────────────┘

   Example 2: Main PC → Robot (Control Command)
   ┌──────────────────┐  /pinky1/  ┌──────────┐           ┌──────────┐
   │     Main PC      │──cmd_vel──▶│  Bridge  │──/cmd_vel▶│  pinky1  │
   │     (D=25)       │             │          │           │ (D=11)   │
   └──────────────────┘             └──────────┘           └──────────┘

   Example 3: Coordinator ↔ Robot Arm (No Namespace)
   ┌──────────────────┐  /arm_a/   ┌──────────┐  /arm_a/  ┌──────────┐
   │   Coordinator    │───cmd─────▶│  Bridge  │───cmd────▶│   armA   │
   │ Main PC (D=25)   │             │          │           │ (D=20)   │
   │                  │◀──status───│          │◀─status───│          │
   └──────────────────┘             └──────────┘           └──────────┘

================================================================================
CONFIGURATION FILES
================================================================================

1. domain_bridge_pinky1_improved.yaml
   - Bridges: Domain 11 ↔ Domain 25
   - Topics: amcl_pose, odom, scan, battery, cmd_vel, initialpose, goal_pose
   - Actions: navigate_to_pose, follow_waypoints
   - QoS: Defined for each topic type

2. domain_bridge_pinky2_improved.yaml
   - Bridges: Domain 12 ↔ Domain 25
   - Same structure as pinky1

3. domain_bridge_arms.yaml
   - Bridges: Domain 20 ↔ 25, Domain 21 ↔ 25
   - Topics: arm_a/*, arm_b/*, verify/*, fms/*, cooking/*
   - Handles multi-domain broadcast (pickup_arrival, cooking/order)

================================================================================
ADVANTAGES OF THIS ARCHITECTURE
================================================================================

✅ Simplicity on Robot Side
   - Robots don't need to know their namespace
   - Standard ROS2 topic names (/cmd_vel, /odom, etc.)
   - Easy to test individually

✅ Isolation on Main PC Side
   - Each robot has unique namespace
   - No topic name conflicts
   - Fleet management possible

✅ Minimal Configuration Changes
   - Only domain bridge configs need namespace
   - Robot code unchanged
   - Coordinator uses simple topic names

✅ Scalability
   - Easy to add new robots (just add new bridge config)
   - No cross-talk between robots
   - Clear separation of concerns

✅ QoS Optimization
   - High-frequency sensor data: best_effort
   - Critical control/status: reliable
   - Static data: transient_local
