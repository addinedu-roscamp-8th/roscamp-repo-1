# 로봇 팔 스트리밍 서버 연동 가이드

영상 분석 서버(이미지 처리 서버)는 **JetBot**뿐 아니라 **로봇 팔 스트리밍 서버**(`robot_arm/image_streaming_server`)를 영상/이미지 소스로 사용할 수 있습니다. 두 서버 모두 동일한 HTTP API(`/snapshot`, `/video_feed`)를 제공하므로, 설정만 바꾸면 됩니다.

---

## 1. 소스 서버 선택

| 소스 | base_url 예시 | 비고 |
|------|----------------|------|
| JetBot (라즈베리파이) | `http://192.168.1.10:5000` | 기존과 동일 |
| 로봇 팔 스트리밍 서버 | `http://<로봇팔PC_IP>:5000` | 동일 API, WebSocket 옵션 지원 |

---

## 2. 설정 방법 (Phase 1: HTTP만)

`config/jetbot_config.yaml`에서 **base_url**만 로봇 팔 스트리밍 서버 주소로 변경합니다.

```yaml
base_url: "http://192.168.x.x:5000"   # 로봇 팔 스트리밍 서버 IP:포트

endpoints:
  snapshot: "/snapshot"
  video_feed: "/video_feed"
```

- **코드 변경 없음**. `/analyze/image`, `/analyze/video`, `/analyze/video/stream`, `/stream/preview` 등이 그대로 해당 소스에서 영상을 가져옵니다.
- 로봇 팔 서버의 `/video_feed`는 가로 최대 640px·JPEG 품질 82로 전송될 수 있습니다. 분석 입력이 640 기준이면 그대로 사용 가능.

---

## 3. WebSocket 영상 수신 (Phase 2, 선택)

로봇 팔 스트리밍 서버는 **WebSocket `/ws/video`**로 JPEG 프레임을 푸시합니다. 지연 감소가 필요할 때 사용합니다.

### 3.1 설정

`config/jetbot_config.yaml`의 `video` 섹션에 다음을 추가/수정합니다.

```yaml
video:
  use_websocket: true        # true면 영상 스트림을 WebSocket으로 수신
  ws_video_path: "/ws/video" # base_url 기준 WebSocket 경로 (기본값)
```

- `use_websocket: false`(기본): 기존처럼 HTTP MJPEG `/video_feed` 사용.
- `use_websocket: true`: `base_url`을 `ws://`로 변환한 뒤 `ws_video_path`에 연결해 프레임 수신. **GET /analyze/video**, **GET /analyze/video/stream**, **GET /stream/preview** 등 영상 스트림을 쓰는 API가 모두 WebSocket 소스를 사용합니다.

### 3.2 의존성

WebSocket 클라이언트 사용 시 `requirements.txt`에 다음이 포함되어 있어야 합니다.

```
websocket-client>=1.6.0
```

`pip install -r requirements.txt`로 설치됩니다.

### 3.3 동작 요약

- **스냅샷**(`/analyze/image`, `/analyze/arm_cmd`)은 계속 HTTP **GET /snapshot**만 사용합니다.
- **영상 스트림**이 필요한 API만 `use_websocket` 설정에 따라 HTTP MJPEG vs WebSocket 중 하나로 동작합니다.

## 4. 로봇 팔 서버 상태 확인

로봇 팔 스트리밍 서버의 **GET /health**로 소스 상태를 확인할 수 있습니다.

```bash
curl http://<로봇팔_IP>:5000/health
```

응답 예: `{"ok": true, "camera_ready": true, "device": "/dev/jetcocam0"}`
