YOLO 분석 서버 API 문서

JetBot 영상/이미지를 가져와 YOLO로 객체 검출 후 JSON으로 반환하는 Flask API

개요

Base URL: http://<서버IP>:5001 (포트는 config/server_config.yaml 또는 환경변수 YOLO_SERVER_PORT, YOLO_SERVER_HOST로 변경 가능)

Content-Type: application/json (요청/응답 공통)

에러 시: HTTP 4xx/5xx + JSON body에 success, error, message 등 포함

공통 에러 응답

HTTP 코드의미JSON 예시
503 소스 연결 실패 (JetBot 스냅샷/영상 가져오기 실패) {"success": false, "error": "source_fetch_failed", "message": "..."}
500 서버 내부 오류 (YOLO 추론 실패, 모델 로드 실패 등) {"success": false, "error": "inference_failed", "message": "..."}

엔드포인트 목록

메서드경로설명
GET/API 정보 및 엔드포인트 목록
GET/health서버·모델 상태 확인

1. API 정보

GET/

서비스 설명과 사용 가능한 엔드포인트 목록을 반환합니다.

Request

Body 없음. Query 없음.

Response 200 OK

{
  "service": "yolo-analysis",
  "description": "YOLO 기반 영상/이미지 분석 API (JetBot 소스 연동)",
  "endpoints": {
    "health": "/health",
    "model_info": "GET /model_info",
    "analyze_image": "GET /analyze/image",
    "analyze_video": "GET /analyze/video",
    "analyze_video_stream": "GET /analyze/video/stream (SSE)",
    "stream_preview": "GET /stream/preview (MJPEG)",
    "view": "GET /view",
    "reload_model": "POST /reload_model",
    "analyze_arm_cmd": "GET /analyze/arm_cmd",
    "interface_spec": "See INTERFACE_SPEC.md"
  }
}

2. 헬스 체크

GET/health

서버 동작 여부 및 YOLO 모델 로드 상태를 확인합니다.

Request

Body 없음. Query 없음.

Response 200 OK

{
  "status": "ok",
  "model": "loaded"
}

모델 로드 실패 시 model 필드에 "error: <메시지>" 형태로 들어갑니다.

3. 모델 정보

GET/model_info

현재 사용 중인 YOLO 모델의 절대 경로, 파일 존재 여부, 클래스 목록, 로드 상태를 반환합니다.

Request

Body 없음. Query 없음.

Response 200 OK

{
  "model_path": "/path/to/best.pt",
  "model_path_exists": true,
  "class_names": ["Hamcheese", "Mushroom", "All-in-one", "NG"],
  "load_status": "loaded"
}
필드설명
model_path로드에 사용된 모델 파일 절대 경로
model_path_exists해당 경로에 파일 존재 여부
class_namesconfig에 정의된 클래스명
load_statusloaded | file_not_found | load_error: ...

Error 500

{
  "error": "...",
  "model_path": null,
  "model_path_exists": false,
  "class_names": [],
  "load_status": "error: ..."
}

4. 이미지 분석

GET/analyze/image

JetBot /snapshot에서 이미지를 다운로드한 뒤 YOLO 분석 결과를 반환합니다. 호출 측은 이미지를 전송할 필요 없이 GET만 하면 됩니다.

Request

Body 없음. Query 없음.

Response 200 OK

{
  "success": true,
  "source": "snapshot",
  "image_size": { "width": 640, "height": 480 },
  "detections": [
    {
      "class_id": 0,
      "class_name": "Hamcheese",
      "confidence": 0.92,
      "bbox": [100, 150, 300, 400]
    }
  ],
  "count": 1
}
필드타입설명
detections[].class_idint클래스 ID
detections[].class_namestring클래스 이름
detections[].confidencefloat신뢰도 (0~1)
detections[].bbox[x1,y1,x2,y2]바운딩 박스 픽셀 좌표

Error 503

{"success": false, "error": "source_fetch_failed", "message": "Connection error ..."}

Error 500

{"success": false, "error": "inference_failed", "message": "..."}

5. 영상 분석 (일괄)

GET/analyze/video

JetBot /video_feed 스트림에서 프레임을 읽어 YOLO 분석 후, 프레임별 검출 결과를 묶어 반환합니다.

Request

Query타입설명
num_framesint optional분석할 프레임 수. 생략 시 config 기준(기본 5)

Response 200 OK

{
  "success": true,
  "source": "video_feed",
  "num_frames": 5,
  "frames": [
    { "frame_index": 0, "image_size": {...}, "detections": [...], "count": 1 }
  ],
  "detections": [...],
  "total_detections": 3
}

Error 503

{"success": false, "error": "source_fetch_failed", "message": "..."}

Error 500

{"success": false, "error": "inference_failed", "message": "...", "frame_index": 2}

6. 이미지 분석 + ROS2 토픽 발행 (로봇 팔 연동)

GET/analyze/arm_cmd

스냅샷을 분석한 뒤, 검출 클래스에 따라 ROS_DOMAIN_ID=21 환경에서 /verify/cmd 토픽으로 명령을 발행합니다.

클래스 → 명령: Hamcheese, Mushroom, All-in-one → HANDOFF_PINKY | NG → DISCARD | 검출 없음 → 발행 안 함(또는 config에서 no_detection_command)

Request

Body 없음. Query 없음.

Response 200 OK

{
  "success": true,
  "source": "snapshot",
  "image_size": { "width": 640, "height": 480 },
  "detections": [{ "class_name": "Hamcheese", "confidence": 0.92, "bbox": [...] }],
  "count": 1,
  "command_key": "handoff_pinky",
  "ros_published": {
    "success": true,
    "command": "handoff_pinky",
    "data": "j1|HANDOFF_PINKY",
    "returncode": 0,
    "message": "ok"
  }
}
필드설명
command_keyhandoff_pinky | discard | null
ros_published서버가 실행한 ros2 topic pub 결과. 없으면 null

Error 503

{"success": false, "error": "source_fetch_failed", "message": "...", "ros_published": null}

Error 500

{"success": false, "error": "inference_failed", "message": "...", "ros_published": null}

7. 영상 분석 스트리밍 (SSE)

GET/analyze/video/stream

JetBot /video_feed 스트림을 실시간으로 읽어, 프레임마다 YOLO 분석 결과를 Server-Sent Events로 전송합니다.

Request

Query타입설명
max_framesint optional최대 전송 프레임 수. 생략 시 stream_timeout_seconds까지

Response 200 OK

Content-Type: text/event-stream. 각 이벤트: data: <JSON>\n\n

{"frame_index": 0, "image_size": {"width": 640, "height": 480}, "detections": [...], "count": 1}

에러 이벤트 (스트림 내)

{"error": "source_fetch_failed", "message": "..."}
{"error": "inference_failed", "message": "...", "frame_index": 3}

8. 스트리밍 프리뷰 / 뷰 페이지

GET/stream/preview

JetBot 영상을 받아 프레임마다 YOLO 분석 후, bbox와 "Detected: ..." / "No detection" 문구를 그려 MJPEG 스트리밍. Content-Type: multipart/x-mixed-replace; boundary=frame

GET/view

위 스트림을 보여주는 HTML 페이지. 브라우저에서 /view 로 접속하면 영상과 검출 여부를 함께 볼 수 있습니다.

9. 모델 재로드

POST/reload_model

config/yolo_config.yaml 변경 후 서버 재시작 없이 YOLO 모델만 다시 로드할 때 사용합니다.

Request

Body 없음 (또는 빈 JSON {}).

Response 200 OK

{"success": true, "message": "Model reloaded from config."}

Error 500

{"success": false, "error": "모델 파일을 찾을 수 없음 ..."}

설정 파일 요약

파일용도
config/yolo_config.yaml모델 경로(model_path), 클래스명(class_names), 추론 옵션
config/jetbot_config.yamlJetBot base URL, /snapshot, /video_feed, 프레임 수·타임아웃
config/arm_ros_config.yamlROS_DOMAIN_ID, /verify/cmd 토픽, 클래스→명령 매핑
config/server_config.yaml서버 host, port (기본 5001)
